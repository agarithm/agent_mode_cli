# agent_mode_cli
Answering the question: What happens when you give the LLM bash?

Inspired by [You Should Write an Agent](https://fly.io/blog/everyone-write-an-agent/) by Thomas H. Ptacek, @tqbf.


## Overview

This repository builds three command-line tools from a shared Python core library under `src/`:

- **`ai`** - Agent-mode CLI (full REPL) with dynamic provider switching (Ollama default)
- **`am`** - Compatibility alias for `ai` (defaults provider to OpenAI)
- **`om`** - Compatibility alias for `ai` (defaults provider to Ollama)

The canonical build artifacts are **single-file Python scripts** in `dist/`, generated by `./build`.

Internally, `am` and `om` share a universal context representation and provider-specific adapters so additional AI backends can be added without changing the core agent loop.

## Requirements

- Python **3.10+**
- Python deps: `pip install -r requirements.txt`
- For Ollama-backed tools (`ai`, `om`): the `ollama` executable installed and available on `$PATH`
- Optional: `glow` for nicer streaming output in `ai` (falls back to plain output if missing)

If you keep secrets in `~/.secrets` as `export ...` lines, you can load them once per shell:

```bash
set -a
source ~/.secrets
set +a
```

## Build

Build standalone single-file scripts into `dist/`:

```bash
./build --out dist
```

This produces:

- `dist/ai`
- `dist/am`
- `dist/om`

Each file embeds the shared library from `src/agent_mode_cli/**` and runs via an in-memory importer.

Note: `dist/` is generated output. Whether you commit it or not is up to you; this repo’s `.gitignore` currently ignores it.

## Deploy / Install

`./deploy` copies built files from `dist/` to a destination directory.

Deploy into this repo’s `bin/`:

```bash
./deploy
```

Or install into a user bin directory (recommended):

```bash
./deploy --dest ~/.local/bin
```

Make sure your install directory is on `$PATH` (example):

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Note: `bin/` is a deployment target (generated files). Don’t hand-edit deployed scripts; edit `src/` and rebuild.

## Usage

### `ai` - Unified Agent REPL (Multi-provider)

`ai` is now the primary UX: a full agent-mode REPL that can switch providers in the same chat session.

**Defaults / behavior:**

- Default provider: `ollama` (override with `AI_PROVIDER`)
- Default model: `gpt-oss` (override with `AI_MODEL`)
- Like `om`, it will auto-detect NVIDIA GPUs (when `nvidia-smi` is present) and auto-start `ollama serve` unless `OLLAMA_HOST` is set.

**Provider switching commands (local, not sent to the model):**

- `help` (or `:help`) – show REPL commands and settings knobs
- `providers` (or `:providers`) – list available providers
- `use <name>` (or `:use <name>`) – switch provider (e.g. `use openai`)

Other local settings commands:

- `settings` (or `:settings`) – show current settings
- `debug on|off` – toggle debug logging
- `model <name>` – set the model for the current provider
- `max_tool_iterations <n>` – set the tool-loop iteration watchdog
- `max_tool_seconds <sec|off>` – set the tool-loop time watchdog

**Usage:**
```bash
ai
ai "What is the capital of France?"

# Inside the REPL:
> providers
> use openai
> use ollama
```

### `am` - Compatibility Alias (OpenAI)

Runs the unified `ai` REPL with the provider preselected to **OpenAI**.

In addition to `bash`, the agent also has web retrieval tools:

- `web_fetch` – lightweight HTTP(S) fetch (no JavaScript), with basic HTML-to-text extraction
- `js_web_fetch` – JavaScript-enabled fetch via Playwright/Chromium (use when `web_fetch` is insufficient)

**Danger:** This tool can execute arbitrary bash commands on your local machine. Prefer using it in a container/VM.

**Prerequisites:**
- OpenAI API key via `OPENAI_API_KEY`

**Setup:**
```bash
export OPENAI_API_KEY='your-api-key-here'
# Optional:
export AM_MODEL='gpt-5.1-codex'   # default used by `am` if not set
export AM_DEBUG=1                # enable verbose debug logs (use 0 to disable)
export AM_PROMPT_FILE=~/.am_prompt  # optional extra system prompt
```

**Usage:**
```bash
am
am "What is the capital of France?"

# Inside the REPL:
> providers
> use ollama
```



### `om` - Compatibility Alias (Ollama)

Runs the unified `ai` REPL with the provider preselected to **Ollama**.

**Environment:**

- `OM_MODEL` – overrides the default model (`gpt-oss`)
- `OM_DEBUG` – enable verbose logs
- `OM_PROMPT_FILE` – optional extra system prompt file (default: `~/.om_prompt`)
- `OLLAMA_HOST` – point to a remote Ollama instance (skips local auto-start)

Like `ai`, it will auto-detect NVIDIA GPUs (when `nvidia-smi` is present) and will auto-start `ollama serve` unless `OLLAMA_HOST` is set.

**Usage:**
```bash
om
om "List files in the current directory"

# Inside the REPL:
> providers
> use openai
```

The agent will invoke local tools as needed. When it wants to run `bash`, you’ll be prompted to confirm (with an approve-all option per user prompt).

## Running From Source (dev)

Use the dev wrapper script to run the tools directly from `src/` (no `dist/` build needed):

```bash
./run_test ai what is the capital of france
./run_test om what is the capital of france
./run_test am what is the capital of france
```

Tip: this wrapper is named `run_test` to avoid conflicts with the `test` shell builtin.

## Browser Tooling Notes

If you want `js_web_fetch` to work, you need Playwright’s Chromium installed (in addition to the Python package):

```bash
python -m playwright install chromium
```
