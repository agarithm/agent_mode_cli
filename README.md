# agent mode cli
Answering the question: What happens when you give the LLM bash?

Inspired by [You Should Write an Agent](https://fly.io/blog/everyone-write-an-agent/) by Thomas H. Ptacek, @tqbf.

Also, see [Geoffrey's How to Buiild a Coding Agent](https://ghuntley.com/agent/).


## Overview

This repository builds a single command-line tool from a shared Python core library under `src/`:

- **`ai`** – Agent-mode CLI (full REPL) with dynamic provider switching (Ollama default)


The canonical build artifacts are **single-file Python scripts** in `dist/`, generated by `./build`.

Internally, `ai` uses a universal context representation and provider-specific adapters so additional AI backends can be added without changing the core agent loop.

## Providers

Provider-specific code lives under `src/providers/`:

- `providers/openai/` – OpenAI adapter + runtime helpers + tool schema
- `providers/ollama/` – Ollama adapter + runtime helpers + tool schema
- `providers/copilot/` – GitHub Copilot adapter + runtime helpers + tool schema

## Requirements

- Python **3.10+**
- Python deps: `pip install -r requirements.txt`
- For Ollama-backed tools: the `ollama` executable installed and available on `$PATH`

If you keep secrets in `~/.secrets` as `export ...` lines, you can load them once per shell:

```bash
set -a
source ~/.secrets
set +a
```

## Build

Build standalone single-file scripts into `dist/`:

```bash
./build
```

This produces:

- `dist/ai`

Each file embeds the shared library from `src/**` and runs via an in-memory importer.

Provider failover is driven by the active provider's fallback list (see `src/entrypoints/ai.py`). When a provider reports a rate limit, the runner temporarily marks it unavailable and automatically switches to the next configured provider.


## Deploy / Install

`./deploy` copies built files from `dist/` to a destination directory.

Deploy into this repo’s `bin/`:

```bash
./deploy
```

Or install into a user bin directory (recommended):

```bash
./deploy --dest ~/.local/bin
```

Make sure your install directory is on `$PATH` (example):

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Note: `bin/` is a deployment target (generated files). Don’t hand-edit deployed scripts; edit `src/` and rebuild.

## Usage

### `ai` - Unified Agent REPL (Multi-provider)

`ai` is the primary UX: a full agent-mode REPL that can switch providers, models, and runtime settings mid-session.

**Defaults / behavior:**

- Default provider: `ollama` (override with `AI_PROVIDER`)
- Default model: `gpt-oss`  (override with `AI_MODEL` per provider)

**Local / settings commands (not sent to the model):**

- `help` (or `:help`) – show REPL commands and settings knobs
- `:settings` – show current settings snapshot
- `:settings provider <name>` or `:provider <name>` – switch providers
- `:settings model <name>` or `:model <name>` – set the current provider model
- `:settings max_tool_iterations <n>` – set the tool-loop iteration watchdog
- `:settings max_tool_seconds <sec|off>` – set the tool-loop time watchdog

**Usage:**
```bash
# Plain REPL with defaults
ai

# Inline provider/model selection before the REPL starts
ai openai
ai openai gpt-4.1
ai copilot

# Inside the REPL:
> :provider openai
> :model gpt-4.1
> :provider ollama
```

## Running From Source (dev)

Use the dev wrapper script to run the tool directly from `src/` (no `dist/` build needed):

```bash
./test
./test openai gpt-4.1
```
## Ollama Setup
To use the Ollama provider, you need to have the Ollama CLI installed and a local Ollama model running.
1. Install the Ollama CLI by following the instructions on the [Ollama website](https://ollama.com/docs/installation).
2. Download and run a local Ollama model. **NOTE**: We must have a model that supports tool calling: `gpt-oss` is recommended.  See other tool models at [Ollama Models](https://ollama.com/search?c=tools).
