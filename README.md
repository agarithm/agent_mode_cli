# agent_mode_cli
Answering the question: What happens when you give the LLM bash?

Inspired by [You Should Write an Agent](https://fly.io/blog/everyone-write-an-agent/) by Thomas H. Ptacek, @tqbf.


## Overview

This repository builds four command-line tools from a shared Python core library under `src/`:

- **`ai`** - Agent-mode CLI (full REPL) with dynamic provider switching (Ollama default)
- **`am`** - Compatibility alias for `ai` (defaults provider to OpenAI)
- **`om`** - Compatibility alias for `ai` (defaults provider to Ollama)
- **`cm`** - Compatibility alias for `ai` (defaults provider to GitHub Copilot)

The canonical build artifacts are **single-file Python scripts** in `dist/`, generated by `./build`.

Internally, `ai` and the compatibility wrappers share a universal context representation and provider-specific adapters so additional AI backends can be added without changing the core agent loop.

## Providers

Provider-specific code lives under `src/agent_mode_cli/providers/`:

- `providers/openai/` – OpenAI adapter + runtime helpers + tool schema
- `providers/ollama/` – Ollama adapter + runtime helpers + tool schema
- `providers/copilot/` – GitHub Copilot adapter + runtime helpers + tool schema

To add a new provider, follow the short guide in `src/agent_mode_cli/providers/README.md`.

## Requirements

- Python **3.10+**
- Python deps: `pip install -r requirements.txt`
- For Ollama-backed tools: the `ollama` executable installed and available on `$PATH`

If you keep secrets in `~/.secrets` as `export ...` lines, you can load them once per shell:

```bash
set -a
source ~/.secrets
set +a
```

## Build

Build standalone single-file scripts into `dist/`:

```bash
./build
```

This produces:

- `dist/ai`
- `dist/am`
- `dist/om`
- `dist/cm`

Each file embeds the shared library from `src/agent_mode_cli/**` and runs via an in-memory importer.

Provider failover is driven by the active provider's fallback list (see `src/agent_mode_cli/ai/app.py`). When a provider reports a rate limit, the runner temporarily marks it unavailable and automatically switches to the next configured provider.


## Deploy / Install

`./deploy` copies built files from `dist/` to a destination directory.

Deploy into this repo’s `bin/`:

```bash
./deploy
```

Or install into a user bin directory (recommended):

```bash
./deploy --dest ~/.local/bin
```

Make sure your install directory is on `$PATH` (example):

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Note: `bin/` is a deployment target (generated files). Don’t hand-edit deployed scripts; edit `src/` and rebuild.

## Usage

### `ai` - Unified Agent REPL (Multi-provider)

`ai` is now the primary UX: a full agent-mode REPL that can switch providers, models, and runtime settings mid-session.

**Defaults / behavior:**

- Default provider: `ollama` (override with `AI_PROVIDER`)
- Default model: `gpt-oss` (override with `AI_MODEL` per provider)

**Local / settings commands (not sent to the model):**

- `help` (or `:help`) – show REPL commands and settings knobs
- `:settings` – show current settings snapshot
- `:settings provider <name>` or `:provider <name>` – switch providers
- `:settings model <name>` or `:model <name>` – set the current provider model
- `:settings max_tool_iterations <n>` – set the tool-loop iteration watchdog
- `:settings max_tool_seconds <sec|off>` – set the tool-loop time watchdog

**Usage:**
```bash
ai
ai "What is the capital of France?"

# Inside the REPL:
> providers
> use openai
> use ollama
```

### `am` - Compatibility Alias (OpenAI)

Runs the unified `ai` REPL with the provider preselected to **OpenAI**.


**Prerequisites:**
- OpenAI API key via `OPENAI_API_KEY`

**Setup:**
```bash
export OPENAI_API_KEY='your-api-key-here'
# Optional:
export AM_MODEL='gpt-5.1-codex'   # default used by `am` if not set
export AM_DEBUG=1                # enable verbose debug logs (use 0 to disable)
export AM_PROMPT_FILE=~/.am_prompt  # optional extra system prompt
```



### `om` - Compatibility Alias (Ollama)

Runs the unified `ai` REPL with the provider preselected to **Ollama**.

**Environment:**

- `OM_MODEL` – overrides the default model (`gpt-oss`)
- `OM_DEBUG` – enable verbose logs
- `OM_PROMPT_FILE` – optional extra system prompt file (default: `~/.om_prompt`)
- `OLLAMA_HOST` – point to a remote Ollama instance (skips local auto-start)


## `cm` - Compatibility Alias (Copilot GitHub Models)

Runs the unified `ai` REPL with the provider preselected to **Copilot / GitHub Models**.

**Credentials:**

- Set `GITHUB_TOKEN` (recommended) or `GH_TOKEN` to a GitHub token that can call GitHub Models.
	- Fine-grained PAT: grant **Models: Read**
	- Classic PAT: include the `models` scope

**Defaults:**

- `CM_MODEL` defaults to `xai/grok-3`.
- `CM_FALLBACKS` (optional) lets you specify a comma-separated fallback order (e.g. `openai,ollama`).


## Running From Source (dev)

Use the dev wrapper script to run the tools directly from `src/` (no `dist/` build needed):

```bash
./run_test ai what is the capital of france
./run_test om what is the capital of france
./run_test am what is the capital of france
./run_test cm what is the capital of france
```
